# 📸 Interview-Level Screenshot Guide

Capture these from your own Postman/Newman execution and save them with the suggested names.

| # | Filename | What should be visible |
|---|---|---|
| 01 | `01_GET_User_Response.png` | GET URL, `200 OK`, response JSON and passing tests |
| 02 | `02_POST_Create_Post.png` | POST body, `201 Created`, response and assertions |
| 03 | `03_PUT_Update_Post.png` | PUT request, updated JSON and passing tests |
| 04 | `04_PATCH_Update_Post.png` | PATCH body, updated title and status |
| 05 | `05_DELETE_Post.png` | DELETE request and response |
| 06 | `06_Negative_Test_404.png` | Invalid ID, `404 Not Found` and passing negative assertion |
| 07 | `07_Collection_Runner.png` | Collection Runner summary and test counts |
| 08 | `08_GitHub_Actions.png` | Successful Newman GitHub Actions workflow |

## Screenshot quality checklist

- Keep the Postman request name visible.
- Keep method and endpoint visible.
- Keep HTTP status visible.
- Keep the response body readable.
- Keep the Tests/results area visible where possible.
- Crop unnecessary desktop content.
- Use consistent naming and ordering.
- Do not edit test results or create fake pass/fail evidence.

These screenshots are the strongest visual proof of the work when an interviewer opens the repository.
